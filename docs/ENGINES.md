# Мультипротокольное приложение: текущая граница и план интеграции

0.3.0: Python получил адаптер к внешнему obfs4 SOCKS5 PT. Это не универсальный
SOCKS-прокси и не интеграция obfs4 в Android/iOS; внешний движок не включён и
здесь не испытан. См. LOOK_LIKE_RANDOM.md.

Обновление 0.2.0: собственный SEVER-1 теперь передаётся через HTTPS/WebSocket.
Это изменение транспорта не добавляет поддержку VLESS, OpenVPN, AmneziaWG или
других сторонних протоколов. В Android зарегистрирован только `sever1`.

Полной поддержки «всех возможных протоколов» у этой версии нет. Она требует
отдельных реализаций, совместимости форматов, лицензий и испытаний каждой комбинации.
Слово «Amnezia» также обозначает приложение/семейство; интеграция AmneziaWG не
автоматически добавляет все протоколы и варианты контейнеров AmneziaVPN.

## Матрица

| Протокол/семейство | Предполагаемый движок | В этом архиве | Что необходимо сделать |
|---|---|---|---|
| SEVER-1 | Написанные здесь Python / Java / Swift | Сервер и исходники клиентов | Собрать, проверить на устройствах и реальной сети |
| VLESS, VMess, Trojan, Shadowsocks | Xray-core / libXray | Не интегрирован | Выбрать закреплённую версию, встроить мобильную обвязку, связать пакетный TUN с proxy data plane, проверить DNS/UDP |
| AmneziaWG | Официальные мобильные реализации AmneziaWG | Не интегрирован | Согласовать версию сервера и поля конфигурации; встроить движок Android/iOS |
| WireGuard | WireGuard Android tunnel / WireGuardKit | Не интегрирован | Сборка библиотек, управление TUN и жизненным циклом |
| OpenVPN | OpenVPN 3 Core | Не интегрирован | JNI/Swift обвязки, TLS-профили, сертификаты, проверки совместимости |
| Hysteria2, TUIC и другие QUIC-протоколы | Отдельные движки или совместимое ядро | Не интегрированы | Выбрать ядро, проверить поддержку на обеих ОС и TUN-мост |
| IKEv2/IPsec | Системные API/отдельный движок | Не интегрирован | Отдельная конфигурация профилей и разрешений |
| SOCKS5 / HTTP proxy | Прокси-адаптер | Не интегрирован | TUN-to-proxy и явные гарантии транспорта; SOCKS5 сам не обеспечивает шифрование |

Это **план**, не перечень работающих переключателей. Совместимость конкретных
серверных транспортов, REALITY, UDP и импорта должна подтверждаться тестами
закреплённой версии, а не названием ядра.

## Контракт Android

`TunnelEngine` задаёт `start()` и `close()`; `EngineRegistry` содержит фабрики
встроенных движков. Сейчас зарегистрирован только `sever1`. `SeverVpnService`
создаёт его через реестр. Добавляемый адаптер компилируется вместе с приложением
и регистрируется во время Application startup; загрузки исполняемого кода из
подписок нет.

Текущий `Profile` описывает только профиль SEVER-1. При добавлении других движков
нужно ввести раздельные типы `SeverProfile`, `XrayProfile`, `OpenVpnProfile` и т.д.,
каждый с собственным валидатором. Одной регистрации фабрики недостаточно.

Адаптер должен:

1. Защитить свои транспортные сокеты от попадания в собственный VPN.
2. Получить разрешение системы через общий сервис и быть единственным владельцем TUN.
3. Переводить конфигурацию строго в формат своего движка.
4. Подтвердить готовность после реального handshake/установки маршрутов.
5. Отдавать настоящий статус, ошибки, трафик и результат проверки соединения.
6. Завершать потоки/сокеты/дескрипторы в `close()` до запуска другого движка.
7. Работать с секретами через Keystore/Keychain; не выводить их в логи.

На iOS пока реализован только конкретный `PacketTunnelProvider` Север-1. Для
мультидвижкового extension потребуется выделение транспорта в отдельный адаптер
и диспетчер, работающий с `packetFlow`. Нативные профили IKEv2 могут требовать
другого пути через Network Extension и не обязаны использовать тот же extension.

## Обновления конфигурации

Для ранее обсуждавшейся задачи «сменить порт без раздачи нового профиля каждому»
следующий самостоятельный компонент — control plane:

- Стабильный device ID и секрет устройства отдельно от адресов VPN-серверов.
- Подписанный список серверов/портов/допустимых движков, ограниченный срок действия.
- Проверка подписи, монотонной версии и запрет отката на старые данные.
- Кеш последней подтверждённой конфигурации и несколько независимых адресов обновления.
- Атомарное переключение: рабочий профиль сохраняется до проверки новой версии.
- Отзыв устройства, ротация ключей, QR enrolment с одноразовым короткоживущим кодом.

Control plane, подписи и QR пока отсутствуют. HTTPS сам по себе не заменяет
проверку подписанной конфигурации при выбранной модели доверия.

## Порядок работ до продукта

1. Собрать Север-1 и проверить VPN на Android/iPhone и тестовом VPS.
2. Подключить Xray, AmneziaWG и OpenVPN — это минимальный набор из запроса.
3. Добавить нормализованный импорт, тесты несовместимых конфигов и реестр возможностей.
4. Реализовать обновления endpoint, переключение движков и восстановление после смены сети.
5. Выполнить сетевые/нагрузочные тесты и независимый обзор безопасности.
6. Подготовить подпись, обновления, диагностические отчёты без секретов и распространение.

Сторонний код не включён в архив. До встраивания закрепите commits, сохраните
license/notice и проверьте условия распространения всей сборки. Юридическая
совместимость не установлена этим документом.
