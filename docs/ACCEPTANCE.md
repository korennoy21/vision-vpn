# Приёмка на стенде — ещё не выполнена

Дополнение для 0.2.0: локальные проверки WSS и двух наблюдаемых признаков уже
описаны в VERIFICATION.md и OBSERVABILITY.md. Эта страница относится к оставшейся
проверке на настоящих ОС, nginx, VPS и сетях операторов.

Каждый результат отмечать для конкретного телефона, ОС, версии приложения,
оператора, региона, даты, транспорта и сервера. Результат одной сети не является
гарантией для остальных операторов или последующих блокировок.

## Минимальная функциональность

| Проверка | Ожидаемый результат |
|---|---|
| TLS-сертификат правильный / неправильное имя / истёк / недоверенный CA | Подключение только к доверенному серверу с совпадающим именем |
| Правильный / неверный / отозванный профиль | Доступ только с действующим профилем |
| Внешний IPv4 до и после подключения | После подключения — адрес тестового VPS |
| DNS через TCP/UDP, веб, большие загрузки, UDP-приложение | Данные проходят через VPN; нет обхода туннеля |
| IPv6 | Блокируется в этой версии, не идёт напрямую |
| Два устройства с разными профилями | Оба работают; пакеты адресованы правильному устройству |
| Один профиль на двух устройствах | Вторая сессия отклонена; первая сохраняется |
| STOP, отзыв разрешения VPN, перезапуск приложения | Сокеты/FD освобождены; статус совпадает с ОС |
| Неподдерживаемый протокол при импорте | Явная ошибка, отсутствует ложный статус «подключено» |

## Смена сетей и отказ

- Wi-Fi → LTE/5G → Wi-Fi; роуминг; авиарежим; изменение IP и NAT.
- Выключение сервера во время загрузки; восстановление; недоступный первый endpoint.
- Экран выключен 30 минут/2 часа, режим экономии энергии, выгрузка приложения.
- Проверить утечки захватом пакетов на стороне LAN и VPS, включая период
  переподключения. UI-счётчик и ключик VPN сами по себе этого не доказывают.
- Android: отдельно проверять с системной блокировкой соединений без VPN и без неё.
- iOS: отдельно фиксировать поведение includeAllNetworks и исключений ОС.

## Производительность

Измерить медиану и p95 времени подключения, RTT, throughput, расход батареи,
CPU/RAM сервера, стабильность 1/10/30 клиентов. Сравнить с существующим VPN на
том же VPS, устройстве и сети. Затем добавить воспроизводимые задержки/потери
на своём тестовом маршрутизаторе. Целевые численные значения согласуются после
первых измерений; этот прототип не имеет заявленной скорости.

## Обнаруживаемость

Сохранить разрешённые тестовые pcap своих подключений: ClientHello, распределение
размеров/интервалов, поведение до AUTH, во время простоя и больших передач.
Проверить, не выделяется ли padding регулярным рисунком. Отдельно исследовать
реакцию собственного сервера на некорректные соединения и активные проверки.

Нужны сравнительные испытания в реальных сетях. Локальный TLS-тест не измеряет
реакцию ТСПУ. Даже успешные испытания позволяют заявить только «работало в таких
условиях на такую дату», а не «невидимо для РКН».

## Условие готовности

До выполнения пунктов выше, встраивания минимальных сторонних движков,
проверок лицензий, независимого обзора безопасности и подписанных сборок статус
проекта — **экспериментальная разработка**, не готовый VPN для раздачи клиентам.
