# Переход с 0.1.0 на 0.2.0

Внешний транспорт изменён с собственного потока внутри TLS на WebSocket внутри HTTPS. Старые и новые мобильные клиенты не взаимозаменяемы. Пользователи и IP-адреса сервера совместимы.

1. Сохраните старые исходники, unit, сертификаты, users.json и профили.
2. Подготовьте зависимости, nginx, сайт и сертификат по LINUX.md на тестовом узле.
3. Остановите старый `sever`, установите новый unit и запустите loopback backend.
4. Настройте nginx; проверьте конфигурацию и обычные веб-запросы.
5. Преобразуйте профиль, явно указав фактический HTTPS-порт:

```bash
python3 tools/migrate_profile.py старый.profile.json \
  --out новый.profile.json --port 443 --path /api/session
```

Скрипт сохраняет `user` и `token`, создаёт отдельный файл с mode 0600, не перезаписывает исходный профиль. Он меняет все endpoints на указанные port/path; если серверы используют разные порты, отредактируйте их явно. В users.json ничего менять не нужно.

6. Соберите клиенты 0.2.0, импортируйте новый профиль и переподключитесь.
7. Проверьте VPN через Wi-Fi и мобильную сеть по ACCEPTANCE.md.

Новый профиль:

```json
{
  "version": 2,
  "protocol": "sever1",
  "transport": "wss",
  "name": "Мой телефон",
  "endpoints": [{"host": "vpn.example.com", "port": 443, "path": "/api/session"}],
  "user": "device-01",
  "token": "ЗАМЕНИТЬ_РЕАЛЬНЫМ_ТОКЕНОМ_ИЗ_ПРОФИЛЯ"
}
```

Пример не является рабочими учётными данными. Список серверов всё ещё обновляется импортом JSON: сервер подписок в этой версии не реализован.
