# Наблюдаемые признаки: локальное сравнение 0.1.0 и 0.2.0

Дата: 09.09.2026. Это инженерный тест двух признаков, не эмуляция ТСПУ и не доказательство нераспознаваемости.

## Метод

`tools/compare_observables.py` создаёт временный тестовый сертификат и два локальных режима. Старый режим воспроизводит алгоритм padding 0.1.0 поверх raw TLS; текущий совместимый Gateway используется как получатель. Новый режим использует настоящий aiohttp WebSocket поверх TLS 1.3.

Между клиентом и сервером поставлен TCP relay, который пересылает **нерасшифрованные** байты и сохраняет длины TLS-записей клиента. Relay не получает ключей TLS. Handshake и CONFIG исключены из окна измерения. Затем идут 100 прикладных PING с ожиданием PONG после каждого.

Это захват байтов TCP-потока в процессе, не pcap и не реальная сеть оператора. nginx, Android/OkHttp и iOS/URLSession в этом эксперименте не участвовали.

## Результаты одного запуска

| Показатель | Старый режим | Новый WSS |
|---|---:|---:|
| PING / TLS application records | 100 / 100 | 100 / 100 |
| Число разных длин TLS records | 2 | 93 |
| Минимальная длина | 273 | 52 |
| Максимальная длина | 529 | 550 |
| Разные остатки длин по модулю 256 | 1 | 82 |
| Обычный GET / по TLS | EOF, 0 байтов ответа | HTTP 200, 73 байта содержимого тестового сайта |

Длины не включают 5-байтный TLS header. WebSocket framing и шифрование уже включены в наблюдаемый новый поток. Из-за случайных значений следующие запуски дадут другие точные числа.

Полные массивы длин: [observables.json](observables.json).

Дополнительные тесты проверяют: GET/HEAD сайта, одинаковые status/body/content-type для неизвестного ресурса и неавторизованного Upgrade, отсутствие 101 и WWW-Authenticate без действующего профиля, запрет HTTP-redirect с секретом, отклонение неправильного сертификата, реальный IPv4/PING обмен внутри WSS.

## Что можно заключить

- Прежнего принудительного округления до 256 нет.
- Публичную архитектуру перевели на настоящий веб-транспорт; тестовое приложение обслуживает обычные HTTP-запросы.
- Туннель не открывается до авторизации; обычные проверки без профиля не получают CONFIG.

**Нельзя заключить:** что новый поток похож на репрезентативный браузерный трафик, что классификатор не отличит его, что неизвестные пробы не дадут отличий, что nginx развёрнут правильно или что ТСПУ не сможет блокировать VPN.

Равномерный padding, длительный поток, TLS fingerprint, SNI, IP, тайминги, асимметрия, объём и поведение при отказах остаются потенциальными признаками. Случайность сама по себе не является маскировкой. Статистическая эффективность не измерена; нет датасета обычных приложений, независимого классификатора и оценки ложных срабатываний.

Для воспроизведения:

```bash
.venv/bin/python tools/compare_observables.py --samples 100
```

Для полевой проверки нужны ваш тестовый VPS и устройства в сетях операторов. Успешные соединения показывают доступность, но не позволяют наблюдать внутреннее решение ТСПУ о классификации.
