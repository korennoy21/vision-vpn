# VISION Control 1.2.0

## Сайты / активность клиентов

VISION Control 1.2.0 добавляет наблюдаемость назначения трафика без MITM и без расшифровки HTTPS.

Панель показывает для VISION Secure/WSS клиентов:
- домены, увиденные в обычном DNS;
- публичный IP назначения, если домен определить не удалось;
- время первого и последнего обращения;
- приблизительное число соединений;
- DNS-запросы;
- переданный и полученный трафик;
- фильтр по клиенту и периоду.

Полные URL, содержимое HTTPS, формы, сообщения и пароли не собираются. Для DoH/DoT/ECH или приложений со своим защищённым DNS домен может быть недоступен — тогда, если включена соответствующая политика, отображается только публичный IP.

## Серверный сбор

В VISION Node добавлен bounded `ActivityCollector`:
- распознавание DNS A-запросов/ответов;
- временное сопоставление `домен → IPv4` по DNS TTL;
- агрегация счётчиков в памяти;
- пакетная отправка в VISION Control через авторизованный `/agent/activity`;
- сбой телеметрии активности не разрывает VPN-сессию;
- при отключении сбора буферы активности очищаются.

## VISION Control Web

Добавлен раздел **«Сайты / активность»**:
- все клиенты или конкретное устройство;
- период 1 час / 24 часа / 7 дней / 30 дней;
- домен/IP, протокол, DNS-запросы, соединения, RX/TX;
- очистка истории;
- настройки хранения 1–365 дней;
- возможность полностью отключить сбор активности;
- возможность не хранить IP-only назначения.

В 1.2.0 также включены hotfix 1.1.1/1.1.2: надёжный Enter на форме входа, cache-busting статических файлов и корректное скрытие login/workspace через `[hidden]`.

## Android VISION Control 1.2.0

Android-admin остаётся защищённой HTTPS WebView-оболочкой над VISION Control, поэтому новый раздел появляется в приложении автоматически после обновления сервера. Версия проекта повышена до 1.2.0.

## Ограничение движков

Серверный сбор в этой версии работает для встроенного **VISION Secure / WSS** data plane, поскольку именно VISION Node видит его IP-пакеты. WireGuard/AmneziaWG/OpenVPN/Xray, запущенные отдельными внешними движками, потребуют отдельного DNS/flow exporter либо централизованного выхода через VISION Node, чтобы их активность отображалась в этом разделе.
